PEDAGOGICAL CORE: DETERMINISTIC PROTOCOLS VS. ISOLATED IMAGE SILOS

Help students see that IIIF is an open network contract, not a software application. Before IIIF, archives were closed silos forcing researchers to download multi-gigabyte files. With the IIIF Image API, a client requests exact mathematical crops and resolutions on demand. In the Presentation API, the abstract Canvas separates the intellectual surface from physical raster files, enabling multi-spectral overlays and side-by-side collation in Mirador.

COORDINATE INTEGRITY & ZERO-ORIGIN SYNTAX

Emphasize that the IIIF Image API {region} syntax (x,y,w,h) uses width and height for the third and fourth values, whereas the TEI <zone> element uses lower-right absolute coordinates (lrx, lry). Students frequently confuse these two coordinate conventions: IIIF w = lrx - ulx and h = lry - uly.

# TEI Zone:  ulx="400" uly="600" lrx="1600" lry="1400"

Classroom Diagnostics & Troubleshooting Triage

  • Trap 1: Coordinate Confusion: Student inputs lrx, lry into IIIF URL. Remind: IIIF takes x,y,width,height, not x1,y1,x2,y2.
  • Trap 2: Aspect Ratio Distortion: Specifying both w,h without an exclamation point (!w,h) forces stretching. Use w, or ,h to preserve proportions.
  • Trap 3: Missing Canvas Dimension: In Presentation API 3.0 manifests, a Canvas must declare explicit integer width and height matching the master coordinate system.
  • Trap 4: Destructive Editing: Warn students never to overwrite the master raw capture. Always output processed results to a derivative filename.
