THE COLLABORATION OBJECTIVE: PEER REVIEW AS SCHOLARLY APPARATUS

A digital scholarly edition is not an isolated desktop document. Today we introduce GitHub remote workflows. A Pull Request is not merely a code-review tool; it functions as a living apparatus criticus where scholars debate readings and provide evidence before adopting text into the master edition.

INVIOLABLE PEDAGOGICAL BOUNDARIES

1. Main branch protection: Never commit experimental draft markup directly to the main branch. All new work must occur on descriptive feature branches.
2. Fork-and-pull governance: Use personal forks to draft changes; submit Pull Requests to the shared upstream repository.
3. Syntax gate after merge: Immediately after editing a merge conflict in VS Code, running xmllint --noout is mandatory before staging to ensure no conflict markers survive.
4. Descriptive PR titles and checklists: Every Pull Request must include a clear summary, manuscript image reference, and verification checklist.
5. Module 10 assignment alignment: Today's hands-on conflict resolution prepares students for Assignment: Module 10 (Consolidation & CI/CD), due Friday, November 13, at 11:00 PM.
