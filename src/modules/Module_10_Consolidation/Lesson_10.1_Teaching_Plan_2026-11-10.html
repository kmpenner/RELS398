THE COLLABORATION OBJECTIVE: PEER REVIEW AS SCHOLARLY APPARATUS

A digital scholarly edition is not an isolated desktop document. Today we learn the working vocabulary of git: thirteen words, each with a clear time and place of use. With that vocabulary in hand, Friday's pull request, merge, and conflict work becomes a sequence of familiar moves rather than a set of mysteries.

INVIOLABLE PEDAGOGICAL BOUNDARIES

1. Main branch protection: Never commit experimental draft markup directly to the main branch. All new work must occur on descriptive feature branches.
2. One step, one commit: Commit a finished step with add then commit -m and a message that says why.
3. Validate before commit: Run xmllint --noout before staging any TEI file.
4. Push the branch, not main: git push origin <branch>; merging into main happens through a pull request on Friday.
5. Module 10 assignment alignment: Today's vocabulary prepares students for Friday's in-class conflict and validation work; Assignment: Module 10 is due Friday, November 13, at 11:00 PM.
