THE SUSTAINABILITY DIRECTIVE: ARCHITECTURE MATCHES PROJECT REALITY

No single DH publication framework fits every team. Server-backed platforms (eXist-db / TEI Publisher) power large multi-work repositories with faceted search when dedicated devops exist; Angular/React SPAs (EVT 3, EditionCrafter) impose rigid folder or build assumptions; zero-build static CETEIcean + OpenSeadragon keeps classroom single-witness editions completely readable, forkable, and server-free for decades.

INVIOLABLE PEDAGOGICAL BOUNDARIES

1. Evidence-based platform comparison: Evaluate platforms by concrete engineering trade-offs (backend tax, single <choice> master support, learning curve), not vendor hype (Grallert Companion 2025, Ch. 5; Meneses NTMRS 11, Ch. 8).
2. Clear all QA checks before peer handoff: Fix duplicate IDs, dangling # pointers, unlinked sentences, unsourced notes without <quote>, and missing @resp credits.
3. Constructive, reproducible peer critique: Every peer-review finding must name an exact observation, URL/pane, and actionable TEI/CSS fix (Early Modern Digital Review rubric).
