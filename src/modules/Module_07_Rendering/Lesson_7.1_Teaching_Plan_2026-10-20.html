THE RENDERING OBJECTIVE: CONTENT VS. PRESENTATION

A valid TEI file records what a text is and says; rendering determines how it is presented to human readers. Content and presentation must remain strictly separated. The diplomatic view respects the physical artifact (scribe's lineation, abbreviations, original spellings), while the reading view privileges modern legibility (paragraphs, expanded abbreviations, regularized spellings). Neither view alters the underlying archival XML file.

INVIOLABLE PEDAGOGICAL BOUNDARIES

1. Ground truth comes first: The manual HTML page and decision table authored today serve as the unchanging benchmark against which Wednesday's deterministic XSLT and Friday's AI stylesheet will be audited.
2. Meaningful text stays in HTML, never CSS: Do not use CSS ::before or ::after pseudo-elements to inject editorial text, expansions, or footnote numbers. Screen readers and search indexers must access all words directly in the DOM.
3. Whitespace around <choice>: Ensure whitespace resides outside <choice> tags in HTML markup so switching views neither merges adjacent words nor introduces phantom gaps.
4. Assessment scope: Module 7 work builds directly toward the cumulative Print-Ready Publication Portfolio; there is no separate weekly workshop assignment.

Starter Projection Card B: Dual CSS Toggles

Verified in Chrome: with this rule the generated number and the words share one line. Using <br> instead puts the number alone on the line above it.

/* diplomatic.css */
.orig { display: inline; }
.reg  { display: none; }
.abbr { display: inline; }
.expan{ display: none; }
.sic  { display: inline; }
.corr { display: none; }

/* the line number, generated before the line it numbers */
.lb::before {
  content: "\A" attr(data-n) "  ";
  white-space: pre;
  color: #64748b;
}

/* reading.css */
.orig { display: none; }
.reg  { display: inline; }
.abbr { display: none; }
.expan{ display: inline; }
.sic  { display: none; }
.corr { display: inline; }
.lb   { display: inline; }

Classroom Diagnostics & Cohort Guidance

Common Diagnostic Pitfalls

  • Collapsing Whitespace: Writing <span class="choice"><span class="orig">word </span>...</span> leaves missing whitespace in the reading view. Keep whitespace outside the choice wrapper.
  • Stray Hyphen at a Broken Word: Where the source has Pro-<lb/>vince, dropping the break leaves Pro- vince. The reading view must rejoin the word, or the student must record why the hyphen stays.
  • Colours as the Only Signal: A gap marked only in red disappears on a black-and-white printout and for a reader who cannot tell red from black. Use a shape — a dotted underline, a bracket — not a colour alone.
  • Lost Accented Glyphs: Omitting <meta charset="utf-8"> causes browsers to corrupt French accented characters (é, à) into mojibake. Verify UTF-8 declaration immediately.
  • Direct CSS Overwriting: Students hard-coding inline styles in HTML. Remind them: zero inline styles; all display logic lives in external CSS files.

Cohort Document Specifics
